description: 依 OrderHub 的標準流程修復使用者明確描述的 bug：重現、定位、確認、最小修復、回歸測試與提交。
---

依照以下流程處理使用者描述的 bug：

1. 根據症狀指出可能涉及的頁面與流程，並先確認你對症狀的理解。
2. 從 Controller 往下追蹤到 Service 與 Repository，定位根因。說明根因後，等待使用者確認再修改。
3. 使用最小變更修復問題；不要順手重構或新增套件。
4. 使用 `code-reviewer` 審查變更是否符合 OrderHub 慣例。
5. 補一個回歸測試，確認它會驗證修復前原本失敗的行為；使用 `test-runner` 執行完整測試。
6. 請使用者回頁面實測。確認後以「症狀 → 根因 → 修法」格式建立一個獨立 commit。
